01 / THE APPROACH

Planning is only
the start.

One intent can have several ways to reach the application. CUA-JEV makes those routes explicit, so the decision and its outcome can both be inspected.

01 / INTERPRET

Ground the proposal.

The text model proposes a subgoal and intents against the observed state. The framework resolves references and compiles only the available, legal routes.

02 / CHOOSE

Separate intent from route.

Jev chooses one concrete intent × route candidate. A DOM action, accessibility operation, or scoped tool can serve the same task when the surface supports it.

03 / VERIFY

Check what changed.

Guards constrain execution. Effect checks and independent terminal gates evaluate the resulting application state before the episode can report success.

How to read these results

One card, one run. Actions count committed operations. Jev calls count policy decisions; model calls count planner requests. VLM requests are shown separately. The four runs used DOM, MCP, CLI, and file API routes; they executed no GUI actions and made no VLM calls.

Recordings and timing. Videos show task windows only. Local path bars may be covered and a brief editor launch may be cut. Measured wall time comes from the raw run, so it may differ from the video length. These cases do not establish arbitrary-task reliability, lower model frequency, or a cost advantage.
